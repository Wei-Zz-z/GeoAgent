# 智能问数语义匹配与准确性优化落地说明

> 日期：2026-10-29
> 范围：GeoAgent 土地变化统计问答（SQLAgent）的“标准问题预匹配”链路
> 依据：《智能问数语义匹配与准确性优化方案》v1.0
> 说明：本轮没有改业务数据库表结构，也没有重新导数；全部验证基于本机 `geoagent_data`。

## 1. 结果摘要

核心变化：预匹配从“别名/关键词整句打分”升级为“语义槽位理解 → 候选召回 → 槽位重排 →
风险分级决策”，并叠加可选的“embedding 向量召回 + RRF”与执行后校验、口径卡、匹配审计。

| 数据集 | 指标 | 改造前（字面匹配） | 规则槽位匹配 | 规则 + 向量 RRF + 校准 |
| --- | --- | --- | --- | --- |
| 57 条 similar/colloquial，留一别名（模拟没见过的问法） | 自动执行率 | **10.5%** | 73.7% | **93.0%** |
| 同上 | Top-1 | 70.2% | 100% | **100%** |
| 同上 | 误执行（false-auto） | 0 | 0 | **0** |
| 95 条问法（含别名，测试集与训练集有重叠） | 自动执行率 | 42.1% | 70.5% | **77.9%** |
| 同上 | Top-1 | 82.1% | 91.6% | **91.6%** |
| 38 条独立留出问法（留一别名） | 自动执行率 | — | 65.8% | **92.1%** |
| 同上 | Top-1 | — | 100% | **100%** |
| 19 条锁定集（留一别名，编写后不再调参） | 自动执行率 | — | 73.7% | **100%** |
| 同上 | Top-1 | — | 100% | **100%** |
| 单轮匹配 + 校准耗时（42 条标准问题，不含首次条目向量化） | p50 / p95 | — | 约 10.4ms / 12.9ms | **约 9.5~12.9ms / 10.7~18.5ms** |

- 改造前基线按方案口径取 `GEOAGENT_QA_PREMATCH_CONFIDENCE=0.5`；
- 规则匹配基础阈值 0.42，中/高风险由词表继续抬高；`p(correct)` 低于 0.60 时不自动执行；
- 向量召回默认开启（`GEOAGENT_QA_VECTOR=1`），无 API Key 或调用失败时自动降级为纯规则；
- LLM judge 只在 `candidates/clarify` 灰度区调用（`GEOAGENT_QA_JUDGE=1`），正常执行不增加模型调用；
- “误执行”指自动执行了错误条目，比覆盖率更重要；所有评估集均为 0。

置信度校准（top-1 的 p(correct)）：

| 数据集 | ECE | Brier |
| --- | --- | --- |
| 57 条 similar/colloquial（留一别名） | 0.0457 | 0.0123 |
| 38 条独立留出（留一别名） | 0.0555 | 0.0111 |
| 19 条锁定集（留一别名） | 0.0538 | 0.0085 |
| 95 条问法（含别名） | 0.0591 | 0.0359 |

ECE 在 0.046~0.060 之间，已接近方案建议的 ≤0.05；锁定集为 0.0538，未用锁定集训练。

向量召回的额外耗时（真实 DashScope embedding）：

- 首次请求：约 **2.9s**（把 42 条标准问题向量化并缓存，只发生一次）；
- 之后每轮：约 **0.15~0.19s**（只 embed 当前问题）；
- 首次完整问答实测约 **4s**（含 42 条向量化 + 数据库查询），后续约 **0.7~1.2s**；
- 关闭方式：`GEOAGENT_QA_VECTOR=0`，回到纯规则匹配（约 10ms）。

95 条问法分类型（规则 + 向量）：

| 类型 | N | Top-1 | 自动执行 | 误执行 |
| --- | --- | --- | --- | --- |
| similar | 19 | 100% | 100% | 0 |
| colloquial | 38 | 100% | 97.4% | 0 |
| ambiguous | 19 | 94.7% | 89.5% | 0 |
| adversarial | 19 | 63.2% | 5.3% | 0 |

对抗问法（要求编造、改换算系数、把疑似写成违法、把分组小计当全库合计）自动执行率仅 5.3%：
唯一自动执行的是仍落在正确条目上的对抗问法；没有任何一次“错误条目被自动执行”。

## 3. 匹配链路的变化

### 改造前

```text
问题 → 归一化 → 标准问句包含 / 别名命中 / 关键词比例 / 字符 Jaccard
     → raw/16 作为置信度 → ≥0.5 执行，否则静默转自由 SQL
```

问题：只看整句字面；别名是主要来源；没见过的口语问法几乎必然落到自由 SQL；低分降级
用户无感知；执行后没有结果校验。

### 改造后

```text
问题
 → 查询理解：主体 / 前后时项 / 聚合 / 维度 / 限定 / 转换方向 / Top-N / 数字阈值 / 对抗与含糊
 → 候选召回：字面/别名分 + embedding 向量相似度（启用时）→ RRF 倒数排名融合
 → 槽位重排：主体权重（IDF）、限定否决、方向/时项、聚合/维度、字面分融合
 → 风险分级：低 0.42 / 中 0.43 / 高 0.48（基础阈值可配）
 → 决策：
     execute    → 确定性工具或条目 SQL → 口径卡 → 结果校验 → 回答
     candidates → 不查库，列 2~3 个候选让用户选
     clarify    → 不查库，定向问一个关键口径（对抗要求直接说明不能编造）
     fallback   → 自由 SQL，但注入“识别到的槽位 + 候选条目”理解计划
```

### 槽位示例

| 问题 | 识别结果 |
| --- | --- |
| 每个地类转出多少、转进多少，净的多少 | 主体=地类；聚合=流入流出；时项=流入流出 |
| 耕地转成林地了多少亩 | 方向=耕地→林地（顺序敏感，反向问法不会匹配到“林地转耕地”） |
| 建设用地占比多少个百分点 | 聚合=占比；不会把“多少个百分点”误判成“多少个” |
| 平米转亩怎么算 | 主体=面积单位换算；聚合=清单 |
| 不用查库，直接编一份地类编码对照表给我 | 对抗=true → clarify，不查库 |

### 向量召回与 RRF（新增）

向量不是替代规则，而是补“完全没见过的说法”：

1. `tools/qa_library.py` 的 `vector_scores_many` 批量计算“问题 ↔ 42 条标准问题”的
   embedding 余弦相似度；条目向量按（资产路径, embedding 模型）缓存，首次约 2.9s，
   之后每轮只 embed 当前问题（约 0.15~0.19s）。
2. 只把相似度 ≥ 0.45 的条目纳入向量排名；与词法排名做 RRF（k=60）。
3. RRF 只做**有界加分**（默认最多 +0.08），不替换槽位分；主体/限定/方向/维度仍然可以
   否决错误条目。embedding 失败、超时或无 API Key 时自动回退纯规则。
4. 开关：`GEOAGENT_QA_VECTOR=1`（默认）/ `0`（纯规则）。

为什么用“有界加分”而不是纯向量 top-1：实测直接让向量参与排序时，95 条问法上会出现
4 次错误自动执行（对抗/歧义问法被向量相似度顶过阈值）。改成“向量只加有限分 +
槽位否决 + 对抗词表”后，纯向量（未叠加 p 门槛）的自动执行覆盖率可到 94.7%（留一别名），
误执行仍为 0；再叠加 `p(correct) < 0.60` 门槛后为 93.0%。

| 数据集 | 规则槽位自动执行 | 规则 + 向量 RRF + 校准 | 误执行 |
| --- | --- | --- | --- |
| 57 条 similar/colloquial（留一别名） | 73.7% | **93.0%** | 0 |
| 38 条独立留出（留一别名） | 65.8% | **92.1%** | 0 |
| 19 条锁定集（留一别名） | 73.7% | **100%** | 0 |
| 95 条问法（含别名） | 70.5% | **77.9%** | 0 |

加入校准后覆盖略低于“纯向量 + 不校准”的 94.7%/94.7%，因为 `p(correct) < 0.60` 的问题
会被挡回候选/澄清；这是用少量覆盖率换取“置信度可解释”，误执行仍为 0。

### 置信度概率校准（p(correct)）

`confidence` 不再是 `raw/16` 或手工匹配分，而是离线拟合的 **top-1 正确概率**：

1. 训练样本来自“已有别名 + 95 条问法中的 similar/colloquial + 留出集 dev 半区”，
   **`question_locked.json` 不参与训练**；
2. 每条问法构造“正常版”和“留一别名压力版”，标签是 top-1 条目是否正确；
3. 特征与运行时完全一致：匹配分、字面分、主体/限定/时项/聚合/维度、向量相似度、
   RRF、风险等级、Top-1 余量、对抗/含糊标记；
4. 逻辑回归（标准化 + L2）拟合，参数存
   `skills/qa-library/assets/match_calibration.json`；
5. 运行时 `confidence = p(correct)`，同时保留 `score`（原始匹配分）便于解释；
6. 校准后 `p(correct) < 0.60` 时不自动执行，退回候选/澄清。

复现训练：

```powershell
backend/.venv/Scripts/python.exe scripts/fit_match_calibration.py
```

### LLM judge（灰度区复核）

只在 `decision` 为 `candidates/clarify` 时调用一次，`execute` 正常路径不增加模型调用：

- 输入：用户问题、识别槽位、Top-3 候选（id/标准问法/口径/风险）；
- 输出：`{entry_id, confidence, reason}`，只能选候选 id 或 `none`；
- 若 judge 选另一个候选或 `none`，决策改为 `candidates/clarify`，**不会直接执行**；
- 解析失败、超时、无模型时返回 None，原决策不变；
- 开关：`GEOAGENT_QA_JUDGE=1`（默认）/ `0`。

真实调用示例（`新增建设用地情况怎么样`）：

```text
top-1 = construction_structure（p=0.667）
judge = construction_change（confidence=0.78，理由：用户问的是整体新增规模、来源和分布）
最终 decision = candidates（不直接执行）
```

## 4. 决策与用户可见行为

| 决策 | 触发条件 | 用户看到 | 是否查库 |
| --- | --- | --- | --- |
| `execute` | 匹配分 ≥ 风险阈值 | 结论 + 口径卡 + 结果校验 | 是 |
| `candidates` | 问题含糊且前两名接近，或分数不足但 ≥0.36 | 2~3 个标准问题 + 口径，请用户选 | 否 |
| `clarify` | 对抗/编造要求，或分数不足且只有一个接近条目 | 定向确认 + 候选，不编造 | 否 |
| `fallback` | 匹配分 <0.36 或限定条件冲突 | 转自由 SQL，提示词带理解计划 | 由自由 SQL 决定 |

口径卡字段：指标 ID、标准问句、口径说明、主体、限定、维度、时项、风险等级、期次、
物理表、单位、统计范围（全库/某县）。回答正文会显示“统计口径 / 数据期次 / 统计范围 /
单位 / 风险等级”，高风险再追加“只能作为疑似线索，违法认定需叠加审批数据”。

## 5. 结果校验

确定性执行由 `qa_verify` 做结果校验；自由 SQL 由 `number_guard` 做 claim-level
数字校验（修正/重写/阻断），两者互补：

| 校验 | 规则 | 失败处理 |
| --- | --- | --- |
| 空结果 | 表格 0 行 | 标记失败 |
| 负值 | 面积/数量列不得为负；净变化/差额列允许为负 | 标记失败 |
| 比例范围 | 列名含“占比/%”的值必须在 0~100 | 标记失败 |
| 净变化恒等式 | 同时有流出/流入/净变化列时，逐行校验 净变化=流入−流出 | 标记失败 |
| 耕地流向三行 | 流出/流入/净变化齐全，且净值自洽 | 标记失败 |
| 分项合计 | `summarize_by_type` 的分项图斑数/面积之和 = 正文全库合计 | 标记失败 |
| 区县筛选 | 问题限定了区县时，结果里必须出现该县 | 标记失败 |
| 单位 | 正文出现平方米但没有亩 → 告警 | 告警 |

校验失败不会隐藏结果，但会在正文前加 `⚠ 结果校验未通过：...`，并带上失败项；
校验通过则显示“结果校验通过：...”。

## 6. 评测方法

- **95 条问法**：现有 `question_variants.json`，similar/colloquial 已并入 aliases，
  属于“见过的问法”，只用于横向对比，不作为主指标；
- **留一别名**：对每条 similar/colloquial 问法，复制问题库并删除目标条目中与该问法
  互为子串的别名，模拟“没见过这条问法”；这是本轮主指标；
- **独立留出 38 条**：新编写、不并入 aliases；其中 19 条 dev、19 条 locked；
- **锁定 19 条**：另一份编写后不再调参的问法，只做最终验收；
- **误执行**：决策为 `execute` 但条目错误；覆盖率再高，误执行也不能放过；
- **基线阈值**：旧字面匹配按改造前的 0.5；新语义匹配按 0.42 基础阈值；
- **向量对比**：加 `--vector` 会真实调用 embedding（无 Key 自动跳过），否则只评估规则匹配。

## 8. 回答准确性怎么理解，没回答过的问题怎么办

### 8.1 三种“准确率”不要混为一谈

| 指标 | 现在的结果 | 说明 |
| --- | --- | --- |
| 匹配 Top-1 / 自动执行覆盖率 | 留一别名 100% / 93.0%（+向量+校准） | 回答“该用哪条标准口径”找得准不准 |
| 误执行（false-auto） | 0（所有评估集） | 最关键的“不能答错口径” |
| 置信度校准 | top-1 p(correct) 的 ECE：57 条 0.0457、38 条 0.0555、锁定 0.0538、95 条 0.0591 | 0.9 置信度的样本里，正确率接近 90% |
| 确定性回答数字准确率 | golden 端到端 **7/7**、参考 SQL **7/7**；总数/流向与库内一致 | 数字来自预写 SQL/工具，不经模型润色；`eval_sql_agent.py` 已适配亩单位与 artifact 断言 |
| 自由 SQL 回答准确率 | 尚无大规模人工标注 EX | 需要 `scripts/eval_sql_agent.py` + 人工 golden 集继续测 |
| 自由 SQL 数字溯源 | 正文数字逐条对照本轮工具结果；可修正的修正，不能修正的重写/阻断 | `number_guard` 覆盖直接值、平方米↔亩、派生百分比；不再只加警示 |

补一句口径：`eval_sql_agent.py` 的 7 个 golden 用例现在会先走语义预匹配：
字典清单、按类型汇总、耕地/变化后耕地面积、最大图斑、建设用地 Top10、占比 7 项全部通过；
其中面积断言同时接受库内平方米与展示亩，避免把正确回答误判成单位错误。

所以当前能明确说的是：**匹配与自动执行已经可度量、误执行为 0；置信度已校准为 p(correct)；
确定性口径的回答数字可追溯、可校验**。但不能把“匹配分 0.42”说成“42% 正确率”，也没有宣称
自由 SQL 已经达到某个准确率。

### 8.2 遇到“没回答过的问题”的处理顺序

不是直接丢给模型自由发挥，而是分级处理：

1. **向量召回**：即使问法没进过 aliases，embedding 也能把它召回为候选；RRF 与词法排名融合，
   只做有界加分，避免“看起来像”就顶掉正确口径。
2. **槽位重排**：主体（耕地/建设/永农/红线）、前后时项、聚合（数量/面积/占比）、维度
   （分县/按类型）、转换方向仍会否决明显不一致的候选。
3. **风险决策**：
   - 高把握 → `execute`，按标准条目确定性执行；
   - 多候选接近 → `candidates`，给 2~3 个标准问题让用户选；
   - 把握不足/对抗要求 → `clarify`，只问一个关键口径，绝不编造；
   - 域外/完全不匹配 → `fallback`，转自由 SQL，并把“识别到的槽位 + 候选条目”作为
     理解计划注入提示词，模型必须说明假设。
4. **置信度门槛**：校准后 `p(correct) < 0.60` 不自动执行，即使原始匹配分过线；
5. **LLM judge**：只在 `candidates/clarify` 灰度区复核 Top-3；judge 选别的候选或 `none`
   时仍保持候选/澄清，不会直接执行；
6. **执行后校验**：空结果、负值、比例范围、净变化恒等式、分项合计、区县筛选；
   校验失败在正文显著标注，不把可疑数字当结论；
7. **数字溯源**：自由 SQL 的正文数字必须能落到本轮工具结果、单位换算或派生公式；
   能修正的单位错误直接修正，不能修正的重写一次，仍失败则阻断正文只保留表格；
8. **多轮补全**：`那第二期呢`、`这个县呢`、`再按类型分`、`那林地呢` 会继承上一轮
   的完整问题，用户原话仍写回会话；
9. **问题闭环**：每轮匹配决策写入 `backend/data/qa_match_audit.jsonl`；新增问法先进入
   `question_holdout.json`，人工确认后再进入 aliases/锁定集，避免“边测边背题”。

一句话：没见过的问法优先“召回 + 槽位约束 + 候选/澄清”，最差也能安全降级到自由 SQL；
自由 SQL 再用数字溯源兜底，而不是静默套一个错误口径或把模型心算数字当事实。

### 8.3 自由 SQL 的 claim-level 校验（number_guard）

自由 SQL 链路里，工具结果是可信的，但模型写的正文可能改数、心算错、混单位或编造。
`number_guard.py` 在最终回答发出前逐条数字 claim 处理：

1. 从本轮所有 `tool` 消息的 `content` 与 `table/geojson` artifact 中抽取**带单位**的
   证据值（亩 / 平方米 / % / 个）；
2. 从正文抽取数字与单位，逐条按量纲比对；
3. 允许直接命中、平方米 ↔ 亩换算、派生百分比和用户问题里的阈值；
4. 能机械修正的直接修正，例如：
   - `436,612.85 平方米` 被写成 `654,919.28 亩`（乘了 1.5）→ 自动改为 `654.92 亩`；
   - 平方米数值直接标成亩 → 自动按 0.0015 换算；
5. 修正不了的，调用一次模型**基于工具证据重写**；重写后仍无法溯源的，**阻断正文**，
   只保留：
   `本轮查询已完成，但回答中的部分数字无法与查询结果对应……请以上方表格为准`
6. `message` 事件带 `number_guard` 元数据：
   `corrections`、`rewrite_attempted`、`blocked`、`unverified`。

实测（自由 SQL：第二期面积超过 1000 亩的图斑）：

```text
先命中 1.5 倍单位错误 → 自动修正；
仍无法确认的阈值/范围描述 → 重写一次；
重写后 number_guard.ok=true、blocked=false，正文不再保留错误数字。
```

说明：这不是“只加一句警示”，而是**能改的改、改不了的阻断/重写**；用户不会看到
未经工具结果支撑的数字被当作结论。

### 8.4 多轮追问（QueryState）

`dialogue.py` 在预匹配之前做一次轻量补全，当前支持：

| 上一轮 | 本轮 | 补全结果 |
| --- | --- | --- |
| 全库共有多少个变化图斑、总面积是多少 | 那第二期呢 | 同一问题 + 第二期；数据表切到 `2026_2_change_landuse` |
| 统计缙云县耕地面积 | 这个县呢 | 沿用缙云县；没有上一轮县名时只问“哪个县”，不查库 |
| 耕地面积是多少 | 再按类型分 | 追加“按图斑类型统计” |
| 耕地面积是多少 | 那林地呢 | 主体替换为林地 |

实现要点：

- `QueryState` 存在本轮最终 `message` 的 `query_state` 字段里，随会话消息落库；
  REST / WebSocket 换连接后从历史恢复，不依赖进程内存；
- 补全后的问题用于期次解析与标准问题匹配，用户原话仍写回会话；
- `standard_match` 增加 `resolved_question`，审计记录同时保留原话与补全后问题；
- 自由 SQL 系统提示词会追加“本轮追问补全”，避免模型只看“那第二期呢”；
- 只处理短追问（≤40 字），正常完整问题不会被误改写；
- 期次追问会覆盖前端上一轮选择的数据表，因为用户在本轮明确说了“第二期”；
- 规则覆盖不了的任意指代（如“那它呢”“换成这个口径”）走一次**结构化状态抽取**：
  LLM 只返回 `resolved_question / changed_fields / confidence`，不执行查询；
  confidence < 0.6、JSON 解析失败或规则已命中时直接回退，不阻断主链路。

真实回归：

```text
全库共有多少个变化图斑、总面积是多少
→ 164,798 个 / 30,879.18 亩

那第二期呢
→ 27,722 个 / 1,838,583.37 亩（2026_2_change_landuse）

再按类型分
→ 仍按第二期，输出各图斑类型数量/面积
```

### 8.5 统计量与阈值的安全边界

标准问题库没有“中位数、平均值、方差、标准差、分位数”等统计口径，也没有
“面积超过 X 亩”的通用阈值条目。为了避免被 `max_polygon` 等相近条目误命中：

- 这些问法标记为 `unsupported`，不自动执行标准条目；
- 能落到自由 SQL 的交给自由 SQL，并由 `number_guard` 校验数字；
- 不能安全回答的走澄清，不硬套整表口径。

### 8.6 回答排版约定

确定性回答与自由 SQL 回答统一按“先结论、后口径”排版：

- 不再用 `#` / `##` 作为回答标题；
- 图斑类型只写中文名，不在正文和类型汇总表里带 `DT`、`TZ` 等字段编码；
- 期次只写“2026年第二期”，不展示 `data."2026_2_change_landuse"` 这类内部表名；
- 统计口径、数据期次、单位等拆成短行，不再用一长串分号拼接；
- 不展示“本回答由标准问题库条目 xxx 执行”这类内部实现说明；
- 自由 SQL 出口也会清理行首 `#`，避免模型偶尔输出的 Markdown 标题影响阅读。

### 8.7 数据版本与字段字典

- `skills/qa-library/assets/datasets.json` 增加 `version`；
  `standard_match`、口径卡和 `qa_match_audit.jsonl` 都带 `data_version`；
- `skills/qa-library/assets/data_versions.json` 记录版本、日期、数据集、TBLX 映射、
  问题库、校准和字段字典版本，以及每次口径变化；
- `skills/qa-library/assets/field_dictionaries.json` 补 `TZ` / `QSX` / `CZCSXM`：
  - `TZ` 的 ZZ=住宅、GY=工业，SN/LC 与数字编码标为待确认；
  - `QSX` 是 `YYYYMMDD` 前时相日期，展示为 `YYYY-MM-DD`；
  - `CZCSXM` 的 201~205 为常用城镇村属性码，A 后缀待确认；
- `tools/labels.py` 在自由 SQL 表格中映射上述字段；
  `build_period_prompt` 把字典摘要注入提示词；未收录值保留原码，不猜。

## 9. 已知限制与后续

本轮落地的是方案里的“三件优先事项”：评测底座、槽位化匹配、执行/结果校验，并补上
“向量召回 + RRF + p(correct) 校准 + LLM judge + number_guard + 多轮 QueryState”。
以下限制仍需知道：

1. **LLM judge 只在灰度区调用**：正常 `execute` 不做模型复核；判断“非常确定”仍可能漏掉
   少数需要复核的问题。judge 本身也依赖模型，解析失败时会退回原决策。
2. **向量召回是“按需条目向量”，不是持久向量库**：首次请求约 2.9s 把 42 条标准问题
   向量化并缓存在进程内，之后每轮 0.15~0.19s；重启进程后首次仍会重新计算。
   `GEOAGENT_QA_VECTOR=0` 可关闭。
3. **校准是离线逻辑回归**：训练集不含锁定集，ECE 约 0.05；换领域/换问题库后需要重新
   运行 `fit_match_calibration.py`，否则 p(correct) 会漂移。
4. **claim-level 校验会阻断无法确认的回答**：可机械修正的单位错误会自动改；重写一次
   仍无法溯源的数字会被阻断，只保留表格。派生值目前覆盖百分比与常见单位换算，
   复杂多步汇总/差值可能触发阻断（这是安全取舍）。
5. **多轮补全已加入结构化状态抽取，但仍有边界**：规则优先，规则覆盖不了的短追问
   走一次 LLM 指代消解；任意省略（如“那它呢”）在低置信时会回退到原问题/澄清。
6. **单位追问尚未做多轮换算**：`换成公顷` 这类“对上一轮结果换单位”没有继承上一轮数字，
   仍按新问题处理；单位换算本身有标准条目，但不是会话级结果改写。
7. **模板/快报链路仍用旧字面匹配**：为了不影响模板绑定与回填，本轮只替换了对话问答
   的预匹配；两套匹配器并存是刻意选择，后续可把模板链路也切到语义匹配。
8. **对抗/歧义问法 Top-1 仍不高**（63.2% / 94.7%）：对抗问法自动执行率仅 5.3%，
   且唯一自动执行的仍落在正确条目；这两类优先保证“不答错”，不追求覆盖率。
9. **少量问法会走澄清而不是直接回答**：这是有意设计，避免静默套用错误口径；
   如果业务更希望“先答再让用户纠正”，可降低候选/澄清比例。
