# 养老设施步行与简化驾车可达性试点

## 2026-10-27 杭州全市目录

新增按“区县 → 机构”选择的右侧栏，范围包含杭州13个区县市（含桐庐县、淳安县、建德市）。当前机构资料城市编码仅到330100，区县通过坐标与行政边界空间匹配暂定，不把它表述为核实后的行政归属。机构名录不是完整现状清单，区县零条记录表示现有资料未收录，不表示没有养老机构。

`scripts/prepare_hangzhou_elder.py` 读取同一机构JSON、区县GeoJSON与道路SHP，写入新的输出目录。按区县分别准备步行和驾车数据，生成 `catalog.json`；异常坐标记录保留为不可分析项，地址仅用于展示区县提示，不生成猜测坐标。运行时将 `GEOAGENT_ELDER_DATA_DIR` 指向这一新目录。目录接口只读轻量目录，分析时才加载对应区县和模式的路网，最多缓存两份，避免一次加载全市全部网络。

原拱墅区 `backend/data/elder_access` 保留；切回该目录并重启即可恢复原试点。区县切换只影响目录筛选，不改历史会话或既有分析结果。坐标过远、未准备该模式路网等情况明确报错，不静默套用拱墅区路网。

本地数据目录为 `backend/data/elder_hangzhou_20261027`。现有资料共237条：219条有坐标且可暂定区县，18条暂不可分析；其中3条的区县也无法可靠归属，单列“区县待核实”，所以接口返回14个分组（13个行政区县市加1个待核实组）。219条仍需在实际分析时通过100米道路接入检查，不等同于全部已成功计算。

已检查26份区县/模式数据包；抽查上城、桐庐、淳安步行与建德驾车六档计算成功，桐庐和淳安另有超过100米道路接入上限的记录按预期拒绝。293项全项目回归通过后新增的目录接口检查，已随24项相关专项测试通过；前端构建通过。尚未逐机构验证237条记录或进行实地核验。

## 2026-10-24 驾车试算更新

右侧机构列表可选步行或驾车，并输入假设速度：步行默认4.2（1—6）公里/小时，驾车默认30（5—60）公里/小时。默认计算5、10、15、20、25、30分钟，模式或速度修改后需重新点击分析，不改变历史结果。

参考用户提供的易智瑞《15分钟生活圈设施覆盖分析》中“出行模式+时间阻抗”的设计，但并未调用其ArcGIS工具，也不进行人口覆盖推断。驾车独立加载 `pilot-driving.json`，按机动车道路类型筛选，排除步道、楼梯等；建立有向网络，B双向、F沿原线方向、T逆原线方向。编码依据：https://download.geofabrik.de/osm-data-in-gis-formats-free.pdf 。原始数据来源及道路许可仍待核实。

准备脚本增加 `--travel-mode driving`，驾车选取区界外31公里缓冲包围盒中的道路，保留原始线方向；在60公里/小时、30分钟的距离上限之外留出余量。保持原步行 `pilot.json` 不变，将生成的 `pilot-driving.json` 放在同一运行数据目录即可。缺少驾车数据时明确报错，不退回步行计算。

速度是统一假设，不含实时拥堵、红绿灯等待、转向禁令、停车或上下车时间，尚未逐路应用限速；同层连接策略可能遗漏立交衔接。真实试算中社会福利中心从15分钟起路段长度不再增加，已加提示，不解释为周边全部覆盖。2026-10-24全项目290项测试通过，六档真实驾车计算完成；不是实地准确性验收。

## 使用方式

在原对话页选择“养老可达性评估”。先问“列出拱墅区的养老设施”，再指定一个设施，例如“分析杭州市社会福利中心5、10、15分钟步行可达范围”。同名或多个候选由用户选择，不自动代选。

结果包含设施点、可达路段、分时长彩色展示走廊、统计表和限制说明。可修改步行速度（1至6公里/小时）和时间（最多六个阈值，每个不超过30分钟）。默认4.2公里/小时只是试算假设，不是老年人统一步速标准。驾车参数与限制见上面的更新说明。

地图显示设施名称，点击设施、道路集合或走廊可查看解释。主表区分单次步行距离预算（时间乘速度，含接入段的理论上限，并非测得的最远可达距离）与各分支道路累计长度。走廊面积放入折叠详情，试算警示常驻。旧会话中的历史表格不自动重算，请重新提问查看新版结果。

## 下一步实地与来源核验

先核查杭州市社会福利中心和杭州九如城颐乐养老服务有限公司：前者用于一般路网核查；后者目前5、10、15分钟均为282米可达路段，需要确认是实际孤立路网还是数据缺失，不应直接解释为设施可达性差。

需补充或核实：机构坐标的提供平台及坐标系、实际步行入口坐标或标记、入口至公共道路的可通行路径、周边封闭路段和围墙、桥梁及地下通道的步行连接。每项记录证据来源、日期和核验人；尚无证据时维持待核实，不靠模型猜测修正。完成这些核查后再做同参数多设施对比，不能用展示面积直接排名。

## 方法

1. 读取机构坐标和道路，在米制坐标系中计算距离。
2. 将设施连接到最近道路上的位置，而不是直接连接到路段端点。直线连接距离计入步行时间；超过100米拒绝生成，要求核实坐标和入口。
3. 使用最短路径计算沿路网可达距离，截取时间内可走到的部分路段。同一路段的重叠区间先合并，避免重复计长。
4. 在可达道路两侧生成20米展示走廊，并转为地图坐标。该走廊不是精确服务边界，也不表示走廊内每个位置都可达。

表中“可达路段总长度”是所有可达分支的长度合计，不是一个人在该时长内能走过的总路程。展示走廊面积不是人口覆盖或设施服务面积。

## 当前数据与限制

- 首版范围为杭州市拱墅区，16个空间筛选得到的机构点；不代表该区机构完整名录。
- 路网来自用户提供的2025年浙江省OSM道路整理数据，区界来自提供的行政区划数据；机构表的真实统计日期需进一步核实。
- 机构坐标系未知，经用户确认，暂按WGS84解释并明确标注“试算”。未经核实不能视为精确定位。
- 按道路类型筛选步行路网。只有同层、共享原始顶点的道路连接，不把高架与地面平面交叉直接打通。跨层接续、道路通行权限、入口、围墙、封闭小区等仍待核验。
- 从设施向外分析，不是居民到设施的需求覆盖评价。暂不判断床位充足性、人口覆盖率、设施布局合理性，不支持轮椅通行评价；驾车只提供上述简化试算。
- 若坐标或路网无法分析，返回原因，不画直线圆冒充路网分析结果。

## 数据准备与部署

原始数据不进入代码库。`scripts/prepare_elder_access_pilot.py` 接受 `--facilities`、`--boundary`、`--roads`、`--county-code`、`--road-year` 和 `--output` 参数，生成 `pilot.json` 和 `quality.json`。输出目录已存在时拒绝覆盖。

设施输入为JSON数组，每条包含 `name`、`address`、`coordinates_raw`（经纬度字符串）、`source_row`；详细字段以脚本读取为准。区界为带 `gb` 和 `name` 属性的GeoJSON；当前道路输入需为WGS84，并含 `fclass` 和 `layer` 字段。当前投影与数据准备针对浙江试点，不直接推广到全国。

运行时设置 `GEOAGENT_ELDER_DATA_DIR` 指向包含 `pilot.json` 的目录；不设置时使用 `backend/data/elder_access`。会话目录与业务数据目录分开。模型负责理解问题、选择工具和解释结果，距离与路网计算由程序完成，不由模型估算。

## 验证

`backend/tests/test_facility_access.py` 覆盖路段中点接入、部分路段截取、重叠计长、速度变化、接入耗时、跨层隔离、断开道路、无效参数、设施编号和工具产物协议。单元测试不依赖真实模型、数据库或网络。

2026-10-22：14项专项测试通过；16个真实设施均完成5/10/15分钟计算，路段长度及展示面积随时间非递减。该验证是程序一致性检查，不等于坐标、路网或实地可达性的核验。
